# 当前 Run 模型配置与独立人类写入授权

状态：设计已确认（2026-11-11）；尚未实施，不是操作真实 Run 或部署的授权。完整交互、会话换模核查、明确不做的范围与验收标准见[设计方案](../pending-discussions/run-monitor-layout-and-model-config.md)。

## 决定与原因

为满足“指定未结束 Run 的角色下次使用最新主备配置”，在不修改 Definition Snapshot 的前提下引入 Run 级模型配置，适用于普通 Role 与 Judge，不适用于 Manager 主会话。更新只作用于保存后新登记的派发，不改在途或已登记派发，也不改 catalog、模板或其他 Run；冻结定义保留启动事实，运行期配置表达后续意图，历史实派记录表达当时实际使用的模型，三者不可混写。

GUI 对已通过身份校验的人开放**仅模型配置**的独立写入授权，可修改明确选中的未结束 Run（包括其他工作区），不得伪造固定 Manager 身份走工具授权。每个角色的主备和档位原子保存，目标失效、终态或配置冲突均拒绝而不回退其他 Run、不静默覆盖；Manager 工具保留原有调用者限制。相较于让用户必须先回 Manager 会话发出换模指令，这增加一个有边界的人类控制入口，代价是服务端必须单独校验真实 GUI 授权、精确目标及并发配置版本。

手动指定模型改为更新该角色的 Run 主模型并保留最新备用，而非临时救援 C 后暗中回到冻结 A/B。新主 C 合格故障后才切新备 D，D 后续保持；每次明确更新（含同值或仅修改备用）都让下次新派发从最新主模型重新开始，同一次提交的网络重试不重复重置，普通恢复与重启不刷新轮次。旧派发在新配置保存后失败，不得把未使用的新主当作已失败并消耗新链的备用机会；故障资格、安全收口、不重放外部操作及已接受结果不可撤销的原有边界继续成立。

模型切换不额外替换可复用的 Session：保留子代理身份及上下文，使用宿主正式模型选择机制，在下一次安全派发边界应用，并在冷恢复时恢复选择。相较于按新路由强制 fresh，这避免额外丢失角色上下文，但需要正确处理派发冻结路由、生命周期初始化及配置持久化；原有 `reuse: node` / `continuable`、Judge 独立新判定和显式 respawn 不变，正常 compact 仍有效。

## 与既有决策的关系

- 设计生效范围上，局部替代 [ADR-0005](0005-run-monitor-sidebar-tab.md)“监控绝对只读”的约束，仅开放上述模型配置写入；不增加 resume、reset、终止或任意推进权限，保存也不自动解除 BLOCK。
- 局部替代 [ADR-0004](0004-role-model-fallback-authorization.md)“人工救援 C → 冻结 A → 冻结 B”的配置语义，以及旧在途失败会消耗未实派人工轮次的规则。其故障资格和安全要求不变。用户直接更新所选 Run 的角色，无需首次更新、升级或迁移步骤；未修改的角色保持原状，存量持久化兼容由实现内部保证。
- 不新增配置变更审计；配置版本、去重和历史实派事实用于正确执行，不扩展成配置审计功能。
- 两份旧 ADR 的“已实施”描述仍代表当前代码；本 ADR 只记录已确认的新设计取舍，不宣称代码已经切换。
